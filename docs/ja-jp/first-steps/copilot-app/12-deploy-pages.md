GitHub Pages に Space Quiz をデプロイして、公開できるようにします。Copilot はワークフローの準備とデプロイの案内を行えますが、変更をレビューし、サイトが公開されたことを確認するのはユーザーの役割です。

このレッスンでは、次の操作を行います。

- Copilot に GitHub Pages へのデプロイを構成するよう依頼します。
- マージする前に、ワークフローとプル リクエストをレビューします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、手軽に試す方法が必要です。単一ファイルのサイトを GitHub Pages で公開すると、サーバーやランタイム依存関係を追加せずに、公開 URL から利用できます。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プル リクエストを作成すると、コードがコミットおよびプッシュされる場合があります。このプロンプトを送る前に、承認設定と対象リポジトリを確認してください。**Approve all** が選択されている場合、別途確認が求められるとは限りません。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages にデプロイできるよう準備してください。必要に応じて Web サイトをビルドし、変更が既定のブランチに反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更を含むプル リクエストを作成し、そのリンクと、必要な Pages の設定や権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。停止して、レビューを待ってください。
```

## ワークフローとプル リクエストをレビューする

1. README が、リポジトリにまだ存在しない場合にだけ追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限を含め、プル リクエストの変更をレビューします。
3. マージされていないプル リクエストではなく、既定のブランチからデプロイするワークフローであることを確認します。
4. 必要な修正を依頼し、更新された diff をレビューします。マージを許可する前に、必須のプル リクエスト チェックが成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトは、レビュー済みのプル リクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプル リクエストを確認してから送信してください。承認設定によっては、これらの操作に別途確認が求められない場合があります。

`<PR_NUMBER>` をレビューしたプル リクエストの番号に置き換え、別のプロンプトとして送信します。

```plaintext
このリポジトリのプル リクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使って GitHub Pages を有効にし、必須チェックが成功した後に限り、そのプル リクエストをマージしてください。デプロイが成功するまで監視し、公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、私が何を承認または実行する必要があるかを正確に説明してください。サイトが実際に公開されるまで、成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages の有効化やプル リクエストのマージを行えない場合は、提示された具体的な手順に従います。デプロイが成功し、公開サイトが読み込まれるまで、タスクを完了したと見なさないでください。
